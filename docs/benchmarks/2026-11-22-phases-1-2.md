## Resource controls

`group_rss_mb` is an explicit sampled Linux process-group RSS guard. Actual
combined parent/child usage triggers resource_limited, owned cleanup and Run
failure reconciliation. The detached guard survives client SIGKILL. This is not a
hard allocation bound; shared pages count per process and a child in a new
session can leave the measured process group. Default jobs do not scan procfs.

`aggregate_memory_mb` with an explicit delegated `cgroup_root` implements the
separate kernel cgroup-v2 memory path (disabled swap, group OOM and cgroup.kill).
Invalid/missing delegation refuses the request rather than falling back. Actual
kernel OOM/new-session cleanup tests are present but unaccepted on this host.
The real preflight report records exit 2 because /sys/fs/cgroup is not delegated.
No system controller/delegation was modified. GPU memory containment is absent.

Reproduce actual current-host checks:

```sh
PYTHONPATH=nil-sdk python scripts/accept_execution.py --require-rss --output report.json
# Delegated hosts only; missing capability returns 2, not a pass:
PYTHONPATH=nil-sdk python scripts/accept_execution.py --cgroup-root /absolute/delegated/root --output kernel.json
NIL_TEST_CGROUP_ROOT=/absolute/delegated/root PYTHONPATH=nil-sdk python -m pytest nil-sdk/tests/test_execution_resources.py -q
```

Kernel interfaces follow the [Linux cgroup-v2 documentation](https://docs.kernel.org/admin-guide/cgroup-v2.html).
This remains trusted-code operational containment, not hostile-code sandboxing.
